# Навчальні дедлайни

Невеликий застосунок для планування навчальних завдань. Можна додати назву й дату здачі, позначити завдання виконаним або видалити його. Незавершені завдання впорядковано за датою, прострочені виділено. Список зберігається у браузері через localStorage. Сервер Node.js віддає сторінку, статичні файли та JSON на `/healthz`.

## Локальний запуск

Виконайте команди з кореня репозиторію.

```sh
cd students/bondarenko
docker build -t optima-study-board:local .
docker run --rm -p 127.0.0.1:3000:3000 optima-study-board:local
```

Відкрийте `http://localhost:3000`. Для перевірки виконайте `curl http://localhost:3000/healthz`. Очікувана відповідь `{"status":"ok"}`. На стадії `verify` Dockerfile запускає тести `node --test`. У фінальний образ потрапляє лише `src/`, а застосунок працює від користувача `node`.

## Як працює пайплайн

1. Зміна в `main` або pull request запускає збірку образу, тести та перевірку контейнера через HTTP.
2. Коли `DEPLOY_ENABLED=true`, пуш у `main` публікує образ `DOCKER_USERNAME/optima-study-board` у Docker Hub. Тег образу дорівнює SHA коміту.
3. Terraform читає стан із приватного S3 і використовує блокування. Він створює або оновлює EC2 `t3.micro`, SSH-ключ і Security Group. TCP 3000 доступний для HTTP, а TCP 22 відкритий для поточної IPv4-адреси раннера з префіксом `/32`.
4. Під час першого запуску EC2 встановлює Docker. Пайплайн отримує публічний ключ сервера із системного журналу AWS, перевіряє його при підключенні через SSH, завантажує образ за SHA і запускає контейнер.
5. GitHub Actions перевіряє головну сторінку та `/healthz` за публічною адресою на порту 3000.

GitHub запускає воркфлоу з кореневого каталогу `.github/workflows/`. Скрипт для SSH-деплою міститься в `.github/scripts/` усередині папки проєкту.

## Підготовка AWS та GitHub

Потрібні Docker Hub, AWS із типовою VPC та Terraform 1.10 або новіший. У `infra/bootstrap` описані приватний S3 для стану та окремий IAM-користувач для CI. Запустіть `terraform init`, `terraform plan` і `terraform apply` у цій папці з локальної авторизованої сесії AWS. Створіть ключ доступу лише для виділеного користувача й використовуйте його протягом тесту. SSH-ключ ED25519 створіть окремо для цього проєкту.

У розділі `Settings > Secrets and variables > Actions` додайте секрети.

| Секрет | Призначення |
| --- | --- |
| `DOCKER_USERNAME` | Ім'я користувача Docker Hub |
| `DOCKER_TOKEN` | Токен Docker Hub із правами читання та запису |
| `AWS_ACCESS_KEY_ID` | Ідентифікатор ключа виділеного IAM-користувача |
| `AWS_SECRET_ACCESS_KEY` | Секретна частина ключа виділеного IAM-користувача |
| `EC2_SSH_KEY_B64` | Приватний SSH-ключ ED25519 у Base64 |

У вкладці `Variables` додайте `TF_STATE_BUCKET` зі значенням виходу `state_bucket` з bootstrap і `AWS_REGION` зі значенням `us-east-1`. Увімкніть публічний доступ до образу в Docker Hub, щоб EC2 міг його завантажити. Після налаштування додайте `DEPLOY_ENABLED=true` та зробіть пуш у `main`.

Змінна середовища запуску `PORT` має типове значення `3000`. Під час локального запуску порт публікується лише на `127.0.0.1`. Деплой на EC2 використовує типовий порт.

## Видалення ресурсів після перевірки

1. Встановіть `DEPLOY_ENABLED=false` та дочекайтеся завершення поточного запуску.
2. З локальною авторизованою сесією виконайте `terraform init` у `infra` із параметрами `-backend-config=bucket=НАЗВА_БУКЕТА` і `-backend-config=region=us-east-1`. Передайте той самий публічний ключ через `TF_VAR_ssh_public_key` і допустиму адресу через `TF_VAR_ssh_cidr`, наприклад `192.0.2.1/32`. Виконайте `terraform destroy` і перевірте видалення EC2 та Security Group.
3. Видаліть створений ключ доступу IAM та секрети AWS і SSH із GitHub. Після цього виконайте `terraform destroy` у `infra/bootstrap`, щоб видалити IAM-користувача та тимчасовий S3 зі станом. Для наступного тесту знову виконайте підготовку та оновіть налаштування GitHub.
